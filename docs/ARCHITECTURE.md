# noneDB 4 architecture

How the engine is built from its source and where each responsibility lives. The storage format is in
[STORAGE_FORMAT.md](STORAGE_FORMAT.md), the durability contract in [DURABILITY.md](DURABILITY.md).

## One file to include, modular source

Applications include one file:

<!-- doctest: skip -->
```php
require 'noneDB.php';
```

`noneDB.php` is generated by `tools/build.php` from `src/`. Never edit it directly.

- **Build steps:**
  1. The header `src/header.php`.
  2. Every internal class file of `src/manifest.php` (`files`), as a bracketed namespace block (`namespace noneDB\Internal\... { ... }`).
  3. The public classes (`classes`) in `namespace { ... }`, each assembled from its modules.
- **Checks on the result:**
  - It declares exactly the expected classes and no trait.
  - Braces are balanced.
  - It passes `php -l`.
  - `php tools/build.php --check` fails when `noneDB.php` is not the build of `src/`; CI runs it.
- **File rules:**
  - A class file `src/Internal/<Area>/<Name>.php` holds `namespace noneDB\Internal\<Area>;` and one class `<Name>`.
  - A module `src/<class>/<Module>.php` holds part of a public class's body in a trait. The trait is never loaded; it only helps editors.
  - LF line ends only.

Each internal file imports the PHP functions and constants it uses (`use function`, `use const`). The
compiler then resolves them at compile time: `strlen()`, `count()`, `is_array()`, … compile to their
special opcodes, as in global code, with no namespace fallback at run time.

## Public API and engine

| Class | Role |
|---|---|
| `noneDB` (global) | The public API. It holds one integer, the key of its kernel in `Kernel::$instances`, and delegates every method to a service of that kernel. A dump of it (`var_export`, `json_encode`) shows nothing internal; `__debugInfo()` shows the settings without the key. |
| `noneDBQuery` (global) | The fluent query builder: it compiles its filters, sorts and projections and calls the kernel's Query services. |
| `noneDB\Internal\Core\Kernel` | One instance's engine: its values (settings, per-instance caches) and its services. The composition root. |
| `noneDB\Internal\Cache\Runtime` | Process-wide state shared by every instance: the static caches, the lock registry and lock handles, the counters of `getMetrics()`, the test hooks. One object (`Runtime::get()`). |

### Services

A service is a class with one responsibility. It has the kernel in its constructor.

- **Creation:** the kernel creates a service on first use (`Kernel::__get`). A simple operation builds only the services it needs.
- **Binding values:** when created, a service binds the kernel's and the runtime's values it uses **by reference** (`bind()`). It then reads and writes them as `$this->name`, with the same semantics as one shared object.
- **Handles to other services:** these are bound on first use (the service's `__get`).
- **When the `noneDB` instance is destroyed:**
  - `Kernel::release()` drops all handles between the services and the kernel.
  - Nothing is left for PHP's cycle collector; the memory is freed at once.
- **Cloning:** a cloned instance gets a copy of the kernel with its own values. Only the caches linked to the runtime stay shared; the services of the copy are new.

## Memory

Operations stream: a read over many segments works on one batch of one segment at a time and calls
`CacheManager::evictBetweenSegments()` before the next, so its memory does not grow with the database.

What a process keeps between operations has to pay for itself first. All of it lives in the cache: it counts in the
process's memory, goes least recently used first, and is loaded again when needed (`cacheMemoryLimit`, CONFIGURATION.md).

| Kept | From when | Saves |
|---|---|---|
| Key index arrays (`.kix`) | STORAGE_FORMAT.md §6.4 | Decoding the 12-byte slots per lookup |
| Field index pages, or the whole `.fx` | STORAGE_FORMAT.md §6.5.1 | Reading pages per lookup |
| Global index body, exact map | STORAGE_FORMAT.md §6.5.2 | Probing the file per lookup |
| Data bytes of a segment | See below | An open, a seek and a read per record |

**Data bytes (`RecordIO::heldData()`).** A record read from a file costs about what reading 128 KiB at once does,
whatever the size of the record. So a data file in repeated use is read whole and held, and its records become
`substr()` calls. The bytes are held when all of these are true:

- The database has more than 16 segments. With fewer, the key index arrays already answer cheaply. That mark is set
  when a key index is loaded from its file: a segment whose index the process built itself can hold its bytes in a
  small database too.
- The segment had at least 2 operations, and operations × 128 KiB reach the bytes its key index covers.
- The process holds the shared lock: those bytes are committed, so no rollback can take them back. A writer uses bytes
  that are held already and holds no new ones.
- The process has a limit, and stays under half of it with twice the file's size added. A process with no limit
  holds none, because nothing would bound them.

Held bytes stay valid while the key index keeps its epoch: the bytes it covers can't change within one. Lines newer than
those bytes come from the file. `checkIntegrity()` always reads the disk. Held bytes never change an answer; they
only decide where the bytes come from.

**One lookup per segment.** `FindFilter::segmentMatches()` looks up the key index once per segment and hands it to the
field index and to the read. **Whole segments:** a read of every record of a segment without garbage or tombstones splits the
lines at once (`RecordIO::liveLines()`) and checks each key and offset against the key index; anything unexpected falls
back to the read by position.

## Rules, checked by `tests/Unit/ArchitectureTest.php`

1. **The Query layer knows no files and no format.**
   - Applies to `src/Internal/Query/` and the builder.
   - No file-system calls and no storage names (`.jsonl`, `.kix`, `STORE`, `FORMAT`, `segments/`, …).
   - It works on records and plans and calls the storage services.
2. **Dependencies point inwards.** The engine never uses the query builder; the builder calls the engine's Query services.
3. **The migration tool is separate.** `noneDB.php` declares and references none of its symbols.
4. **No trace of earlier versions** in the engine:
   - no old file names or encodings,
   - no version-dated wording,
   - no PHP-version branches.
5. **One class per file**, in the namespace of its directory.
6. **Tests reach the engine only through `noneDB\Tests\Support\Testing`.** No other internal class is referenced and no Reflection is used.
7. **`noneDB.php` holds only the engine.** No test interface, no fault point, test hook or test counter (`ArchitectureTest::theEngineHoldsNoTestCode`); those are test seams of the test build (below).

`tests/Unit/SourceWriteGuardTest.php` adds the write rule. A function writes a database file only through the write helpers of `Durability\FileIO`: `writeFileAtomic`, `appendToFile`, `fsUnlink`, `fsRename`, `fsTouch`, `fsTruncate`, `fsMkdir`, `fsRmdir`. Each gives what it creates the configured permissions (`setPermissions`). The guard lists the exceptions: lock files, quarantine, rollback, store-level files, backup directories.

## Test build and test interface

`noneDB.php` contains only what the engine needs to run. Code that exists for tests is a **test seam** in `src/`, marked for `tools/build.php`:
- **`// @test`:** a line ending with it (a fault point, a test hook, a counter tests read) is left out of `noneDB.php`.
- **`// @test-begin` … `// @test-end`:** the lines between them are left out too (the fault method).
- **`// @prod`:** a line ending with it is the production form of the `@test` line next to it, and is left out of the test build.

**The test build** (`nonedb_build($root, true)`) keeps the seams. `tests/bootstrap.php` writes it to `tests/build/noneDB.php` (ignored by git) whenever `src/` changed, and the tests and their child processes load it. Both builds come from the same files; they differ only in the marked lines.

**`noneDB\Tests\Support\Testing`** (`tests/Support/Testing.php`) is how tests reach internals. It reaches the engine's classes with closures bound to them, so it also works with `noneDB.php` itself: the smoke scripts load it next to the production build. The hooks and counters exist only in the test build.

| Method | What it gives access to |
|---|---|
| `setFaultHook()` | The fault points |
| `get()` / `set()` | Process-wide values: hooks such as `syncFn`, `flushFn`, `writeFn`, `renameFn`, `mbstringFn`, `osFamily`; counters such as `directoryListings`, `indexStats` |
| `getOf()` / `setOf()` | Values of one instance (settings, caches) |
| `call()` / `callStatic()` | Internal methods of any visibility |
| `engine()` | An object standing for the whole engine of an instance, to bind a test closure to |
| `service()` | The service owning a method |
| `liveInstances()` | The number of live instances |

## Test suites

| Suite | Contents |
|---|---|
| `Unit` | Components alone, the build, the architecture rules, the write guard, exhaustive geometry checks |
| `Integration` | The public API and every documented rule (specification tests), on real files |
| `Crash` | Interruptions at every step (exit and SIGKILL in child processes), torn writes, power-loss artefacts, rollback |
| `Concurrency` | Several processes on one database: locks, the state record, cache validation |
| `Differential` | Results against independent models: fuzzing, index results = scan results, geometry |
| `Migration` | The migration tool against databases the old releases wrote themselves (`tests/Migration/fixtures/`, made by `tools/make-migration-fixtures.php`, not in git) |
| `tests/Performance` | The performance gate (A/B against a baseline), the large-database harness, the benchmarks (scripts, not PHPUnit) |
| `tests/Smoke` | Standalone checks (`NONEDB_PATH` selects the library) |
| `tests/Docs` | `doctest.php`: the examples of the documentation, run against `noneDB.php` |
